Fixed 2026-10-23 on main by `2d4da27c`, and on the StakeHub side by `73bf102`. The three wallet binaries are rebuilt.
- [ ] Z2 step 1b, when it lands ([Z2 plan](z2-advisory-flag-execution-plan-20261022.md)): the fork module, the manifest section, sidecar vendoring and prompt v13. Mostly in the fork and the sidecar; this repository records the hashes.
- [ ] SCT-08: bounded read-only evidence campaign, carried from the current plan ([inventory](../../review/defect-inventory-20260910.md)). Owner: this lane.
- [ ] Per-height vote records for the native reliability input (SCT-08 item 4, [decision](../../review/sct08-evidence-campaign-20261023.md#decision-the-native-reliability-input-2026-10-23)). For every finalized height, the node keeps each requested validator's vote outcome (accepted with vote ID, refused, or no answer by the round deadline), including votes after the quorum, and exports it in the signed snapshot. Without these records the reliability fact is "not available". Owner: this lane. Node change: it adds a stored and exported artifact without changing a consensus or state result, and gets its own qualification if review finds otherwise. **Records done, export open.** Stored on main in the commit "Keep per-height vote outcome records for the native reliability input and export them in the signed snapshot" (the export named in that message is not in it): the proposer of each `transport-peer-certified-batch-round` (CLI and RPC rounds) writes `<data-dir>/block-vote-records/height-<h>.json` after its local apply, once per height, without failing the round (`crates/node/src/block_vote_records.rs`, `transport_runtime.rs`; [runbook](../../runbooks/signed-validator-snapshot-recovery.md#vote-outcome-records-sct-08-item-4)). Late answers are collected by a background writer up to the round deadline, so the round does not wait. Evidence: `peer_round_keeps_a_vote_outcome_record_for_every_requested_validator` (ten validators: one refusing, one silent, one answering after the quorum) failed before the wiring (no record) and passes after it. Open: `snapshot-export-signed` does not carry the records yet. The snapshot file list is fixed per snapshot version (`crates/node/src/consensus_artifacts.rs:4051`), so the export needs a new version that the deployed build cannot import; that is the follow-up. Consensus-v2 precommit outcomes are not recorded, and the records have no retention rule yet.
- [x] The account history index follows block commits. Done on main in the commit "Append account history index rows at block commit so the index follows the chain", and it ships with this release. After the block's receipts are durable, the commit appends its `account_tx` rows to the disk index. The append is idempotent on restart, never fails the commit, and leaves the archive scan in use while the index is behind. `account_tx_index_status` reports `disk_index_lag_blocks` and the disk range against the tip (`crates/node/src/block_finality.rs`, `storage_commit.rs`; [runbook](../../runbooks/account-tx-index.md#following-the-chain)). This is a node change to an operator cache, with no consensus, execution or state-commitment change. Before this, the index built on 2026-10-23 went stale after the next block.
- [x] Bound the account history index rewrite per commit. Done on main in the commit "Append account history index rows in chunked shards per commit instead of rewriting whole files", and it ships with this release. Index schema v3 keeps each account's rows in chunk files of at most 64 rows plus a small head, and `account_tx_index_meta.json` and `account_tx_index.json` hold counts and ranges only; a commit rewrites only the last chunk and head of each touched account and the two metadata files (`crates/node/src/account_tx_disk_index.rs`; [runbook](../../runbooks/account-tx-index.md#layout)). Evidence: on a local fixture chain one commit after 68 rows wrote 16,006 bytes in 6 files, against 148,412 bytes in 4 files under v2, and `account_tx` results are byte-identical after the rebuild (36 of 36 on a v2 data directory written by the previous binary). **The rollout runs `account-tx-index-build` on every validator after the upgrade**: until then the v2 index is reported unsupported in `account_tx_index_status` and reads use the archive scan. Owner: this lane. Operator-cache format change, no consensus change.
- [x] The certified batch round must not deliver to its own validator while holding the store lock. Before the fix, without `--local-apply-before-certified-send`, `transport-peer-certified-batch-round` added the proposer to its own send targets when its topology host was not loopback, while it held the store lease for the whole round (`crates/node/src/transport_runtime.rs:2838`). The local validator service could not open the store, dropped the connection, and the round exited 1 after the peers had committed. On 2026-10-23 this made the view-1 round at 1144 fail: validator-5 did not apply its own block until a peer re-sent it. The view-0 stall at 1144 had a different cause, the default 5 s `--timeout-ms`; precommit replies on this fleet take up to about 20 s, so the sheet passes 60 s ([sheet §8b](https://github.com/postfiatorg/postfiatl1v2/blob/release/exchange-readiness-20261023/deployments/exchange-readiness-20261023/DEPLOY-SHEET.md#8b-view-change-at-1144-2026-10-23--covered-by-the-operators-go-of-the-day)). Done on main in the commit "Apply the certified block locally instead of sending it to the proposer's own validator while the round holds the store": `certified_send_targets_for_round` never returns the proposer, and the default round applies the block through the store it holds after the peer sends (`crates/node/src/transport_protocol.rs`, `transport_runtime.rs`; [runbook](../../runbooks/private-nav-otc-shielded-swap-wan-devnet.md#certified-batch-round-delivery)). Both flags keep their meaning. Evidence: `certified_send_targets_never_include_non_loopback_local_peer_by_default` and `default_peer_round_applies_locally_without_sending_to_its_own_validator` failed before the fix (the round dialed its own non-loopback entry three times and returned an error) and pass after it. Until this release is deployed, every sheet must still carry `--quorum-early-full-propagation --local-apply-before-certified-send`. Owner: this lane. Node change to round delivery; no consensus or state-result change.
- [x] Python fallback gaps (no atomic-swap rows; shifted escrow, NFT and offer indexes). Closed on main by #57 (`1736aebb`, 2026-10-13) and #137. The current plan's row is stale.
- [ ] Still-open candidates of the current plan carry over: draft PRs #43–#46, archive-scan `truncated`, and the other lane's delayed-precommit fix. The delayed-precommit fix is a **consensus change and needs its own qualification**.
